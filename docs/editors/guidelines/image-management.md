# Image Management Guide

This guide provides comprehensive instructions for managing images across all content types on the EDT Research Website, including storage, optimization, naming conventions, and usage best practices.

## Overview

Images are a crucial part of the EDT website, used for:

- Page illustrations and diagrams
- News and event photos
- Publication covers and figures
- Team and partner photos
- Brand assets and logos
- Social media previews

## Storage Locations

### Primary Image Directory: `src/assets/images/`

This is the main location for all website images. Astro automatically optimizes images stored here.

**Advantages:**

- Automatic optimization and responsive sizing
- Build-time processing for better performance
- Type-safe imports in components
- Automatic format conversion (WebP, AVIF)

**Current Organization:**

```
src/assets/images/
├── investigators/          # Team member photos
├── news-covers/           # News and event images
├── partners/              # Partner organization logos
├── INRIA_EDT_*.png       # Program diagrams and architecture
├── uploads/Logo_EDT_*.png        # EDT project logos
├── logo-en.png           # Site logos
├── logo-fr.png
└── logo.svg
```

### Public Directory: `public/`

Use for images that need direct URL access or don't require optimization.

**Use Cases:**

- Favicon and app icons
- Images referenced in metadata
- Large files that shouldn't be processed
- Images used by external services

**Current Contents:**

```
public/
├── favicon.png           # Site favicon
├── FR2030_*.svg         # Government endorsement logos
└── offline.html         # PWA offline page
```

### Naming Conventions

#### General Principles

- Use lowercase with hyphens (kebab-case)
- Be descriptive and specific
- Include relevant context (date, project, type)
- Avoid spaces and special characters
- Use consistent patterns across similar content

#### Content-Specific Patterns

**News and Events:**

```
event-{event-name}-{year}.jpg
press-{topic}-{date}.jpg
workshop-{project}-{season}-{year}.jpg

Examples:
event-models2024-conference.jpg
press-funding-announcement-2024.jpg
workshop-pc1-spring2025.jpg
```

**Publications:**

```
{year}-{first-author}-{short-title}.jpg
journal-{journal-name}-cover.jpg

Examples:
2024-combemale-digital-twin-engineering.jpg
journal-sosym-cover-2024.jpg
```

**Team Photos:**

```
{role}-{lastname}-{firstname}.jpg
team-{group}-{year}.jpg

Examples:
investigator-combemale-benoit.jpg
postdoc-smith-jane.jpg
team-pc1-2024.jpg
```

**Diagrams and Architecture:**

```
{project}-{diagram-type}-{version}.png
architecture-{scope}-{version}.png

Examples:
pc1-workflow-v2.png
architecture-overview-main.png
edt-program-structure.png
```

## Image Specifications

### Technical Requirements

#### File Formats

- **JPG/JPEG**: Photos, complex images with many colors
- **PNG**: Diagrams, logos, images with transparency
- **SVG**: Vector graphics, logos, simple illustrations
- **WebP**: Modern format for web optimization (auto-generated by Astro)

#### Size Guidelines

- **Maximum file size**: 2MB (aim for under 500KB when possible)
- **Minimum width**: 800px for content images
- **Social media**: 1200x630px for optimal sharing
- **Hero images**: 1920px wide maximum
- **Thumbnails**: 400x300px minimum

#### Quality Standards

- **Resolution**: 72-96 DPI for web
- **Compression**: Balance quality and file size
- **Color space**: sRGB for web compatibility
- **Optimization**: Use tools like ImageOptim, TinyPNG, or Squoosh

## Usage by Content Type

### Pages (MDX/Markdown)

#### Basic Usage (Markdown)

```markdown
![Alt text description](../assets/images/diagram.png)
```

#### Advanced Usage (MDX)

```mdx
import OptimizedFigure from '@components/OptimizedFigure.astro';

<OptimizedFigure
  src="/media/uploads/INRIA_EDT_PCs_ATs.png"
  alt="EDT program architecture showing five focused projects"
  caption="Figure 1: EDT Research Program Architecture"
  maxWidth={900}
  loading="eager"
/>
```

`src` must start with `/media/uploads/` — the file needs to already be uploaded there. Any other path (including an imported `src/assets/images/...` file) silently renders no image.

### News Content

#### Frontmatter Reference

```yaml
---
title: "Event Title"
photo: /media/uploads/event-models2024-conference.jpg
---
```

#### Image Requirements

- **Required**: `photo` is a required field on every news entry (`src/content.config.ts`)
- **Location**: upload to `public/media/uploads/`, then reference it as `/media/uploads/<filename>` — real content also uses full external URLs here occasionally
- **Usage**: Automatically displayed in listings and social sharing

### Positions

The `positions` schema (`src/content.config.ts`) has no image field — there is no way to attach a photo to a position entry.

### Publications

The `publications` schema has no `coverImage` (or any image) field either. Figures referenced from publication-related content still go through `OptimizedFigure` with a `/media/uploads/...` path, same as any other page:

```mdx
<OptimizedFigure
  src="/media/uploads/methodology-diagram.png"
  alt="Research methodology flowchart"
  caption="Figure 2: Proposed methodology for digital twin validation"
/>
```

## Image Optimization Workflow

### Pre-Upload Optimization

1. **Resize Images**
   - Use appropriate dimensions for intended use
   - Don't upload unnecessarily large images
   - Consider responsive breakpoints

2. **Compress Files**
   - Use tools like ImageOptim, TinyPNG, or Photoshop's "Save for Web"
   - Aim for good quality at smallest file size
   - Test different compression levels

3. **Format Selection**
   - JPG for photographs and complex images
   - PNG for graphics, diagrams, and images with transparency
   - SVG for logos and simple vector graphics

### Astro Automatic Optimization

Astro automatically optimizes images in `src/assets/images/`:

- Generates multiple sizes for responsive images
- Converts to modern formats (WebP, AVIF) when supported
- Lazy loads images by default
- Provides automatic alt text handling

### Manual Optimization Tools

#### Online Tools

- [TinyPNG](https://tinypng.com/) - PNG and JPG compression
- [Squoosh](https://squoosh.app/) - Google's image optimization tool
- [ImageOptim](https://imageoptim.com/) - Mac app for optimization

#### Command Line Tools

```bash
# ImageMagick for batch processing
magick convert input.jpg -quality 85 -resize 1200x output.jpg

# Sharp CLI for modern optimization
sharp -i input.jpg -o output.jpg --jpeg-quality 85 --resize 1200
```

## Accessibility Guidelines

### Alt Text Requirements

#### Descriptive Alt Text

```mdx
<OptimizedFigure
  src="/media/uploads/INRIA_EDT_PCs_ATs.png"
  alt="EDT program architecture diagram showing five interconnected focused projects: PC1 Model Hybridization, PC2 Architecture, PC3 Development Lifecycle, PC4 Digital Coupling, and PC5 Human Interaction"
  caption="Program structure overview"
/>
```

#### Alt Text Guidelines

- **Be specific**: Describe what's actually in the image
- **Include context**: Explain relevance to surrounding content
- **Avoid redundancy**: Don't repeat caption information
- **Keep concise**: Aim for 125 characters or less
- **Skip decorative**: Use empty alt="" for purely decorative images

### Color and Contrast

#### Accessibility Standards

- Ensure sufficient contrast for text overlays
- Don't rely solely on color to convey information
- Test images with color blindness simulators
- Provide alternative text descriptions for complex diagrams

#### Brand Color Usage

Use EDT brand colors consistently:

- **Primary**: #665BA7 (Scampi)
- **Secondary**: #745037 (Brown)
- **Tertiary**: #8b6f50 (Light Brown)
- **Gray scale**: Based on #c6c0c6

## Performance Considerations

### Loading Strategies

#### Critical Images

```mdx
<OptimizedFigure
  src="/media/uploads/hero-image.jpg"
  alt="Description"
  loading="eager"  // Load immediately (default)
/>
```

There is no `priority` prop.

#### Non-Critical Images

```mdx
<OptimizedFigure
  src="/media/uploads/content-image.jpg"
  alt="Description"
  loading="lazy"
/>
```

### File Size Management

#### Size Targets

- **Hero images**: Under 200KB
- **Content images**: Under 100KB
- **Thumbnails**: Under 50KB
- **Icons/logos**: Under 20KB

#### Optimization Strategies

1. **Choose appropriate dimensions**: Don't use 4K images for 400px display
2. **Optimize compression**: Balance quality and file size
3. **Use modern formats**: Let Astro generate WebP/AVIF versions
4. **Consider lazy loading**: Default behavior for non-critical images

## Version Control and Collaboration

### File Management

#### Adding New Images

1. **Optimize first**: Compress and resize before adding to repository
2. **Use descriptive names**: Follow naming conventions
3. **Organize properly**: Place in appropriate subdirectory
4. **Document usage**: Note where images are used in commit messages

#### Updating Images

1. **Keep same filename**: If replacing existing image
2. **Update references**: If changing filename or location
3. **Test thoroughly**: Ensure images display correctly across site
4. **Consider caching**: Browser caches may need clearing

### Collaboration Guidelines

#### Team Workflow

1. **Coordinate additions**: Avoid duplicate images
2. **Share resources**: Maintain shared image libraries when possible

4. **Review quality**: Have team members review image choices

#### External Contributors

1. **Provide guidelines**: Share this guide with external contributors

3. **Maintain standards**: Ensure consistency with existing images

## Troubleshooting

### Common Issues

#### Images Not Displaying

1. **Check file path**: Verify correct path to image file
2. **Verify file exists**: Ensure image is in repository
3. **Check file extension**: Match exact filename including extension
4. **Clear cache**: Browser cache may show old version

#### Build Errors

```
Error: Image not found at path
Solution: Verify image exists in src/assets/images/ directory
```

```
Error: Invalid image format
Solution: Use supported formats (JPG, PNG, SVG, WebP)
```

#### Performance Issues

1. **Large file sizes**: Optimize images before upload
2. **Too many images**: Consider lazy loading and pagination
3. **Slow loading**: Check image dimensions and compression
4. **Memory issues**: Reduce image sizes and quantities

### Debugging Tools

#### Browser Developer Tools

- **Network tab**: Check image loading times and sizes
- **Elements tab**: Inspect image attributes and sources
- **Lighthouse**: Analyze image optimization opportunities

#### Astro Development

```bash
# Check for image optimization issues
npm run astro check

# Build with verbose logging
npm run build -- --verbose
```
